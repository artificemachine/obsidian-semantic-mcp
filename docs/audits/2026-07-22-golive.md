### `_record_watcher_dimension_failure()` (server.py:459-483) — verified correct
- **Read-merge-write, not blind overwrite**: reads current `failed_paths` via `get_index_state`, dedups, appends, writes back the full merged list — existing failure history preserved.
- **Regex specific enough**: `r"expected \d+ dimensions?, not \d+"` matches only pgvector's real column-mismatch phrasing, confirmed NOT to match the unrelated `"vector must have at least 1 dimension"` (empty-embedding) `DataException`.
- **Never-raises contract honored**: wrapped in its own try/except, matches `set_index_state`'s documented pattern.
- **Tests are non-vacuous**: both new tests (`test_dimension_mismatch_write_failure_recorded_in_index_state`, `test_empty_embedding_data_exception_does_not_call_recorder`) genuinely exercise the exact distinction, not a smoke test. Ran: 2 passed.

### Findings
| Severity | Finding | Evidence |
|----------|---------|----------|
| LOW (new) | `_record_watcher_dimension_failure`'s read-then-write is two separate DB round trips with no row lock (no `SELECT...FOR UPDATE`, no advisory lock like `reindex_lock` uses). Two watcher threads hitting dimension-mismatch on the same vault in the same debounce window could lose-update one path from `failed_paths`. Observability-only (status still correctly flips to `dimension_mismatch`; only the path list can be incomplete), self-heals on the next failing edit — not a data-integrity or functional bug, just a gap in an otherwise carefully-locked codebase. | `server.py:459-483` |
| LOW (unchanged) | Hardcoded log level, dual try/except import idiom, folder-structure deviation — all pre-existing, accepted. | unchanged |
